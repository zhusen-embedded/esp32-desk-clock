# 功耗

## 先说清楚

下面这张表**大部分是设计目标，不是实测值**。手上没有功率计，只有一块万用表，串在 5V 供电线上量过几个点，精度也就那样。

真实量过的只有两行，标了「实测」；其余是按器件手册和代码配置估的，标了「估算」。写在这里是为了以后有设备了能对着补。

| 状态 | 电流 @5V | 来源 |
|---|---|---|
| 背光 10% + Wi-Fi 睡眠（夜间熄屏前的状态） | 约 70 mA | 实测，万用表串测，±5 mA |
| 背光 100% + Wi-Fi 常连 | 没量过 | 估算 220~260 mA |
| 背光 60% + Wi-Fi 睡眠（白天正常用） | 没量过 | 估算 100 mA 左右 |
| 22:00 之后背光 10% | 和第一行差不多 | 实测同第一行 |

## 怎么省的电

### 背光 PWM

LEDC，10 bit 分辨率，5 kHz。

```c
void display_set_backlight(uint8_t percent) {
    uint32_t duty = (1023u * percent) / 100u;
    ledc_set_duty(BL_LEDC_MODE, BL_LEDC_CHANNEL, duty);
    ledc_update_duty(BL_LEDC_MODE, BL_LEDC_CHANNEL);
}
```

频率选 5 kHz 是因为再低会有可见闪烁，再高 LEDC 在低占空比时精度不够。10 bit 是为了暗光下调光平滑——8 bit 的话 10% 就只有 25 级，夜间最低那档会跳。

实测从 100% 调到 10%，电流从大概 220 mA 掉到 70 mA，背光占了整机功耗的大头。

### Wi-Fi modem sleep

`menuconfig` 里开了：

```
CONFIG_ESP_WIFI_SLP_IRAM_OPT=y
CONFIG_ESP_PHY_MAC_BB_PD=y
```

效果是 Wi-Fi 在没数据的时候射频会关掉，靠 DTIM 周期醒来收心跳。代价是延迟变大（几十到几百 ms 不定），对时钟这种场景无所谓。

没量过开和关差多少电流，按理说应该有几十 mA。

### 夜间熄屏

`clock_task` 每秒判断一次：

```c
bool night = (t.tm_hour >= 22 || t.tm_hour < 7);
display_set_backlight(night ? 10 : 60);
```

没做成彻底熄屏（背光 0），因为全黑之后完全不知道设备还活着没有。10% 刚好能看见时间但不刺眼。

## 为什么没做深度睡眠

考虑过 light sleep，但有几个问题：

1. 屏要保持显示，深度睡眠会把 SPI 和屏幕控制器都断掉，醒来要重新初始化，会闪一下
2. 触摸唤醒要配置 GPIO 唤醒源，得改硬件接线
3. 时钟本身要一直走，睡下去就得靠 RTC，而现在没接外部 RTC 芯片

所以现在就是 CPU 一直跑，靠背光和 Wi-Fi 省电。如果以后要做电池版，得重新设计。
